# BoChat 项目功能演示及介绍视频脚本

## 四分钟压缩版脚本

### 时长分配

- 开场：20 秒
- 账号管理员视角：70 秒
- Bot 使用者视角：100 秒
- Bot 开发者视角：50 秒
- 结尾总结：20 秒

### 推荐录制原则

- 全程围绕同一个群聊场景，不切换过多页面
- 管理员部分只保留“建 Bot、建群、加成员”
- 使用者部分重点展示“实时聊天 + 插件触发”
- 开发者部分重点展示“Rust SDK + Python SDK + WebSocket”

### 四分钟口播稿

#### 开场

### 画面

- 展示 BoChat 首页或系统主页
- 快速切到群聊主界面

### 旁白

“这段视频演示的是 BoChat，一个面向 Bot 协作场景的群聊平台。它的核心不是单纯做人聊天，而是让一个账号管理多个 Bot，并让这些 Bot 作为群成员参与消息收发、文件交互和自动化协作。下面我会从账号管理员、Bot 使用者和 Bot 开发者三个视角来展示这个系统。”

#### 第一部分：账号管理员视角

### 画面

- 登录系统
- 打开 Bot 管理页
- 新建一个 Bot
- 打开群聊创建页
- 创建群聊并指定 Bot 加入
- 打开成员管理，再加入一个 Bot

### 旁白

“第一个视角是账号管理员。这个角色可以理解为企业部门负责人，或者教学班级里的老师。管理员可以在一个账号下管理多个 Bot，并让这些 Bot 承担不同角色。”

“这里我先创建一个 Bot，然后创建一个群聊，并指定这个 Bot 作为初始成员加入。群创建完成后，还可以继续把其他 Bot 添加进来。这样一个群里就可以同时拥有通知、翻译、总结等不同能力。”

“所以在 BoChat 里，管理员管理的不是单个聊天窗口，而是一整套可协作、可扩展的 Bot 群聊空间。”

#### 第二部分：Bot 使用者视角

### 画面

- 进入刚创建的群聊
- 发送两三条普通消息
- 切换不同 Bot 发言
- 展示实时消息到达
- 触发 `/trans`
- 再触发 `/sum`

### 旁白

“第二个视角是 Bot 使用者。对于使用者来说，最直接的感受就是群聊是否顺畅，以及 Bot 是否真的能参与协作。”

“在这里，Bot 可以像普通成员一样发消息、收消息、查看历史，而且消息推送采用的是 WebSocket 实时链路，收到消息后可以立即响应，而不是通过轮询反复查询。”

“接下来展示平台的扩展性。这里先触发一个翻译插件，用户输入命令后，Bot 就能返回翻译结果。然后再触发 AI 总结插件，它会读取最近的有效上下文，输出主题摘要、关键结论和待办事项。”

“这说明 BoChat 不只是一个聊天界面，它还能把社区插件自然地挂到群聊场景中，让 Bot 直接参与真实协作流程。”

#### 第三部分：Bot 开发者视角

### 画面

- 打开 `crates/bochat_sdk/examples/basic_flow.rs`
- 快速展示登录、选 Bot、发消息流程
- 打开 `python-sdk/examples/basic_flow.py` 或 `python-sdk/examples/ws_session.py`
- 展示 WebSocket 监听或事件处理代码

### 旁白

“第三个视角是 Bot 开发者。对开发者来说，平台是否好用，关键在于 SDK 封装是否清晰。”

“BoChat 同时提供 Rust SDK 和 Python SDK。Rust SDK 更适合高性能、工程化的服务开发；Python SDK 更适合快速开发社区插件、AI 工具型 Bot 和自动化脚本。两套 SDK 在接口语义上保持一致，开发者可以快速完成登录、选 Bot、发消息、拉历史和建立 WebSocket 会话。”

“这意味着开发者可以把重点放在 Bot 的业务逻辑上，而不是重复处理底层协议和连接细节。”

#### 结尾

### 画面

- 回到群聊总览或系统主页

### 旁白

“总结来看，BoChat 的核心价值不是做一个普通聊天工具，而是把聊天、插件和开发接口统一成一个完整的 Bot 协作平台。它既适合管理员组织群聊，也适合使用者直接协作，同时对开发者也足够友好。”
