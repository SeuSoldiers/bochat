# 群聊权限与入群流程 TODO

## 目标

- 支持群聊可见性：`public`（公开）和 `private`（私密）。
- 明确 Bot 入群流程，覆盖“Bot 主动申请”和“群管理员邀请”两种场景。
- 引入审批链路，保证跨管理员场景下的权限边界清晰。

## P0：群聊可见性模型

- [ ] 创建群聊接口新增可选字段：`visibility`。
- [ ] 默认值为 `public`，兼容现有创建流程。
- [ ] `private` 群仅在有权限时可加入，不走自动加入。

验收标准：

- [ ] 不传 `visibility` 时，创建结果为 `public`。
- [ ] 传 `visibility=private` 时，群状态正确落库并在详情中可读。

## P0：公开群入群规则

- [ ] `public` 群允许任意 Bot 通过群号（`group_code`）发起加入。
- [ ] 满足基础校验（Bot 有效、状态正常）后可直接入群。

验收标准：

- [ ] 非群管理员名下 Bot 能通过群号直接加入公开群。
- [ ] 重复加入有幂等处理（不重复创建成员关系）。

## P0：私密群申请流程（Bot 主动加入）

- [ ] Bot 管理员可通过群号索引私密群，并提交“Bot 入群申请”。
- [ ] 若操作人是 Bot 使用者（非管理员），需先向其 Bot 管理员发起内部申请。
- [ ] Bot 管理员同意后，系统自动把申请转发给群所有者。
- [ ] 群所有者可对最终入群申请执行“同意/拒绝”。

验收标准：

- [ ] 私密群不会被非授权 Bot 直接加入。
- [ ] 能完整追踪申请状态：`pending_admin` -> `pending_group_owner` -> `approved/rejected`。
- [ ] 每次审批都有审计记录（审批人、时间、结果、备注）。

## P1：群管理员邀请 Bot 入群流程

- [ ] 群管理员邀请“自己名下 Bot”时，直接入群。
- [ ] 群管理员邀请“他人 Bot”时，先路由到该 Bot 的管理员审批。
- [ ] Bot 管理员同意后完成入群；拒绝则流程结束并通知发起方。

验收标准：

- [ ] 邀请自己 Bot：无额外审批，直接成功。
- [ ] 邀请他人 Bot：必须经过 Bot 管理员审批后才可入群。
- [ ] 全链路通知完整（发起人、Bot 管理员、群管理员）。

## P1：通用能力与后续实现项

- [ ] 增加审批相关 API（发起、查询、审批、撤回）。
- [ ] 增加通知机制（站内消息或回调事件）。
- [ ] 增加集成测试：公开群直入、私密群申请、跨管理员邀请。
